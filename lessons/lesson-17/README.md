# درس ۱۷ — اعتبارسنجی و ساخت کاربر

## هدف
تابع ساخت کاربر نباید هر داده‌ای را بپذیرد. اعتبارسنجی جلوی ورود دادهٔ نامعتبر به منطق برنامه را می‌گیرد؛ این کار در پروژهٔ واقعی باید در سمت سرور نیز انجام شود.

## ۱. قواعد اعتبارسنجی
برای مدل فعلی:
- نام باید رشته و پس از `trim` غیرخالی باشد.
- سن باید عدد صحیح مثبت باشد.
- نقش فقط `"admin"` یا `"user"` باشد.
- شناسه باید یکتا باشد.
- وضعیت فعال هنگام ایجاد به‌صورت پیش‌فرض `true` است.

## ۲. پیاده‌سازی createUser
```js
function createUser(name, age, role) {
  if (typeof name !== "string" || name.trim() === "") {
    throw new Error("Name must be a non-empty string.");
  }
  if (!Number.isInteger(age) || age <= 0) {
    throw new Error("Age must be a positive integer.");
  }
  if (role !== "admin" && role !== "user") {
    throw new Error('Role must be "admin" or "user".');
  }

  const newId = users.length > 0
    ? Math.max(...users.map(user => user.id)) + 1
    : 1;

  const newUser = {
    id: newId,
    name: name.trim(),
    age,
    role,
    isActive: true
  };

  users.push(newUser);
  return newUser;
}
```

## ۳. چرا Math.max؟
استفاده از `users.length + 1` ممکن است پس از حذف یک کاربر شناسهٔ تکراری بسازد. `Math.max(...users.map(...)) + 1` برای این آرایهٔ آموزشی شناسهٔ بزرگ‌تر را پیدا می‌کند. در سامانهٔ واقعی، شناسه‌گذاری باید مسئولیت پایگاه داده یا سازوکار قابل اتکای دیگری باشد؛ همچنین آرایه‌های بسیار بزرگ محدودیت spread دارند.

## ۴. چرا trim؟
`"  Ali  "` بعد از `trim()` به `"Ali"` تبدیل می‌شود. اما نباید بدون نیاز همهٔ ورودی‌ها را تغییر داد؛ هر قاعده باید با نیاز برنامه هماهنگ باشد.

## ۵. خطاها و تست دستی
```js
try {
  const user = createUser("  Sara ", 22, "user");
  console.log(user);
} catch (error) {
  console.error(error.message);
}
```
ورودی‌های نامعتبر را هم امتحان کن: نام خالی، سن صفر، سن اعشاری، رشته به جای سن، و نقش نامعتبر. تست موفق تنها نیمی از کار است؛ حالت‌های شکست هم باید بررسی شوند.

## ۶. مسئولیت‌ها
تابع باید اعتبارسنجی، ساخت شیء و افزودن به آرایه را انجام دهد و کاربر ساخته‌شده را برگرداند. نمایش خروجی را به فایل اجرا بسپار. این تفکیک بعداً تست‌نویسی را آسان می‌کند.

## تمرین
تابع را پیاده کن و حداقل شش آزمایش بنویس: دو مورد معتبر و چهار مورد نامعتبر. بررسی کن شناسه‌ها تکراری نشوند و نام ذخیره‌شده فاصلهٔ اضافی نداشته باشد.

## مرور
می‌توانم قواعد داده را قبل از ذخیره‌سازی بررسی کنم، خطای واضح بدهم و دادهٔ معتبر را برگردانم.
