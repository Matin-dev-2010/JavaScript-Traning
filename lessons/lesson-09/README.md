# درس ۹ — Optional chaining و Nullish coalescing

## ۱. مشکل دسترسی زنجیره‌ای
اگر ویژگی میانی وجود نداشته باشد، دسترسی معمولی می‌تواند خطا ایجاد کند:
```js
const user = { profile: null };
// user.profile.city ممکن است خطا بدهد
```

## ۲. عملگر ?.
```js
const city = user.profile?.city;
```
اگر مقدار سمت چپ `null` یا `undefined` باشد، کل دسترسی `undefined` می‌شود. برای چند سطح:
```js
const postalCode = user.profile?.address?.postalCode;
```
Optional chaining فقط برای جلوگیری از خطا در مسیرهایی است که نبودنشان قابل قبول است؛ نباید همهٔ خطاهای داده‌ای را پنهان کند.

## ۳. فراخوانی تابع اختیاری
```js
const result = user.onLogin?.();
```
اگر `onLogin` nullish باشد، فراخوانی انجام نمی‌شود. اگر وجود داشته باشد ولی callable نباشد، همچنان ممکن است خطا رخ دهد.

## ۴. ترکیب ?. و ??
```js
const displayName = user.profile?.displayName ?? user.name ?? "کاربر";
```
ابتدا مسیر امن خوانده می‌شود؛ اگر مقدار `null` یا `undefined` باشد، مقدار بعدی انتخاب می‌شود.

## ۵. مثال پروژه
```js
function getCity(user) {
  return user.profile?.address?.city ?? "شهر ثبت نشده";
}
```
این تابع زمانی مفید است که پروفایل اختیاری باشد. اگر شهر اجباری است، بهتر است هنگام اعتبارسنجی خطای واضح بدهیم، نه اینکه همیشه مقدار جایگزین نمایش دهیم.

## تفاوت مهم
- `?.`: دسترسی امن در صورت nullish بودن مسیر.
- `??`: مقدار جایگزین فقط برای null/undefined.
- `||`: مقدار جایگزین برای هر مقدار falsy.

## اشتباهات رایج
- استفاده از `?.` برای پوشاندن دادهٔ خراب یا ساختار اشتباه.
- اشتباه گرفتن `??` با `||`.
- تصور اینکه `user?.name` اگر متغیر `user` اصلاً تعریف نشده باشد همیشه ایمن است؛ ارجاع به شناسهٔ تعریف‌نشده همچنان خطا می‌دهد.

## تمرین
تابعی بساز که از شیء کاربر، نام شهر تو در تو را بخواند؛ اگر پروفایل یا شهر موجود نبود «نامشخص» برگرداند. سپس نسخه‌ای بنویس که صفر را به‌عنوان مقدار معتبر حفظ کند.

## پاسخ نمونه
```js
const city = user?.profile?.address?.city ?? "نامشخص";
const count = suppliedCount ?? 0;
```

## مرور
می‌توانم دسترسی امن و مقدار پیش‌فرض را از هم تشخیص دهم و آن‌ها را ترکیب کنم.
