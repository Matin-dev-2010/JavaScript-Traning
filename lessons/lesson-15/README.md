# درس ۱۵ — مرتب‌سازی و تغییرپذیری

## ۱. sort آرایه را تغییر می‌دهد
```js
const numbers = [10, 2, 30];
numbers.sort();
console.log(numbers); // مرتب‌سازی رشته‌ای پیش‌فرض می‌تواند غافلگیرکننده باشد
```
بدون comparator، `sort` مقدارها را بر اساس ترتیب رشته‌ای مرتب می‌کند؛ برای اعداد comparator بده.

## ۲. مرتب‌سازی عددی
```js
const numbers = [10, 2, 30];
numbers.sort((a, b) => a - b); // صعودی
numbers.sort((a, b) => b - a); // نزولی
```
اگر نتیجهٔ `a - b` منفی باشد، `a` قبل از `b` قرار می‌گیرد؛ اگر مثبت باشد، بعد از آن. برای اعداد معمولی این الگو استاندارد است.

## ۳. مرتب‌سازی کاربران بر اساس سن
```js
const sortedUsers = [...users].sort((a, b) => a.age - b.age);
```
`sort` آرایهٔ اصلی را تغییر می‌دهد؛ spread یک آرایهٔ سطحی تازه می‌سازد تا ترتیب `users` حفظ شود. خود اشیاء همچنان همان مراجع‌اند.

## ۴. مقایسهٔ رشته‌ها
```js
const names = ["Sara", "ali", "Mohammad"];
names.sort((a, b) => a.localeCompare(b));
```
`localeCompare` برای مقایسهٔ رشته‌ها خواناتر است و گزینه‌های محلی‌سازی دارد. ترتیب دقیق ممکن است با زبان و locale فرق کند.

## ۵. mutation در برابر immutability
Mutation یعنی تغییر همان آرایه یا شیء. متدهایی مثل `push`, `pop`, `sort` آرایه را تغییر می‌دهند؛ `map`, `filter` آرایهٔ تازه می‌سازند. تشخیص این تفاوت از باگ‌های ناخواسته جلوگیری می‌کند.

## ۶. مرتب‌سازی پایدار و دادهٔ برابر
در مرتب‌سازی کاربران بر اساس سن، دو کاربر هم‌سن ممکن است ترتیب نسبی یکسانی داشته باشند. اگر ترتیب ثانویه نیاز است، آن را صریح تعریف کن:
```js
const sorted = [...users].sort((a, b) =>
  a.age - b.age || a.name.localeCompare(b.name)
);
```

## اشتباهات رایج
- انتظار مرتب‌سازی عددی از `sort()` بدون comparator.
- مرتب کردن آرایهٔ اصلی بدون قصد قبلی.
- تصور اینکه spread کپی عمیق ایجاد می‌کند.
- نوشتن comparator که در حالت برابر نتیجهٔ نامشخص یا ناسازگار می‌دهد.

## تمرین
کاربران را بر اساس سن نزولی مرتب کن، بدون اینکه ترتیب آرایهٔ اصلی عوض شود؛ سپس در سن برابر نام را معیار دوم قرار بده.

## مرور
می‌توانم comparator بنویسم و تفاوت تغییر آرایهٔ اصلی با مرتب‌سازی نسخهٔ کپی‌شده را توضیح دهم.
